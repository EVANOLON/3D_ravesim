## 四、开发位置策略（内外机分工）

### 结论
**代码开发与单元测试在外部机；GPU 仿真冒烟与 DSH+本地模型最终联调在内部机。** git 仓库是唯一事实源，通过现有离线流程同步。

### 实测依据（外部机 = 当前开发机）
| 项 | 状态 |
|---|---|
| GPU | ❌ WSL 下被系统拦截（`GPU access blocked by the operating system`），无法跑 CUDA |
| fastwave 二进制 | ✅ 已编译（`fast-wave/build-Release/fastwave`，ELF x86-64） |
| Python | ✅ 3.13.5 + numpy 2.1.3 + yaml |
| bfpy（big-fourier 绑定） | ❌ 未安装（仅影响 DiskVector/核外相关单测） |
| 网络/git | ✅ 可用 |

### 分工明细
| 工作 | 位置 | 说明 |
|---|---|---|
| 16 工具编码 + pytest（纯逻辑部分） | 外部机 | material/grid/config/feasibility/results/report 等 12 个工具无需 GPU |
| big-wave DiskVector 单测 | 外部机（补装 bfpy）或内部机 | 需 `maturin develop` 编译 big-fourier |
| GPU 仿真用例（P0 探路、场景 A/B/C 验收、validate_physics 实测） | 内部机 | 唯一可用 GPU + 已编译 fastwave 的位置 |
| DSH + 本地模型 + MCP 联调（C6） | 内部机 | 三件套部署后 |
| 报告/文档 | 任意 | 无环境依赖 |

### 配套措施（保证内外机同一代码）
1. **路径全部配置驱动**：fastwave 二进制路径、sim 输出目录、数据目录经 server 配置注入，不写死绝对路径
2. **环境自检工具**（health_check）：检查 GPU、fastwave、Python 依赖、bfpy、磁盘，内网部署后一键诊断
3. **依赖 pin + 离线 wheels**：requirements.txt 锁版本；外部机 `pip download` 生成 wheels/，内网 `pip install --no-index`
4. **同步走 git**：外部机提交 → `git bundle` / 离线介质 → 内部机拉取；Python 版本内外机保持一致（建议 3.10–3.12，注意外部 3.13 与内部版本可能不同）
